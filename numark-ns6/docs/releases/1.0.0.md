# Numark NS6 1.0.0

The first 1.0 release packages the modular macOS driver, with separate CoreAudio devices named **Numark NS6 Output** and **Numark NS6 Input**, the MIDI bridge, Status app, automatic activation/recovery, and package cleanup of the legacy driver.

## Features and resolved issues

- Four-channel 44.1 kHz Float32 playback and a separate two-channel stereo master/record input. The NS6 hardware provides the master/record mix, including analog sources; the driver does not copy output samples into the input.
- Bidirectional MIDI through separate NS6 USB endpoints, preserving the **Numark NS6** CoreMIDI identity used by Mixxx mappings.
- The login bridge keeps CoreAudio attached to the output and reattaches after USB reconnection. Hardware tests confirmed playback, capture, and MIDI resume without restarting applications.
- The Status app reports firmware and active CoreAudio clients. The installer installs or updates it with the driver and bridge.
- Installer cleanup removes conflicting legacy drivers and helpers; the uninstaller removes driver components while preserving logs and user preferences.
- TikTok LIVE Studio receives audio directly from **Numark NS6 Input**, while Mixxx playback and MIDI remain active.
- Input USB capture now keeps eight bulk-IN reads queued. Earlier captures showed corrupted USB payload lanes and full-scale pops despite zero USB errors, ring starvation, or dropped frames. With eight reads, a 5.5-minute direct capture and simultaneous Mixxx/TikTok use showed no sample jumps, USB errors, dropped frames, or audible pops. This addresses the input transfer scheduling margin without modifying or concealing audio samples.

## Validation and known limits

The automated suite passed 14/14 tests. Hardware validation covered direct input recording, Mixxx playback, TikTok capture, MIDI controls, and simultaneous operation. The extended capture lasted about 5.5 minutes; longer live-stream sessions and other macOS versions remain to be verified.

The TikTok recording sounded muffled when played in QuickTime, while its decoded WAV and an AAC-LC conversion sounded clear. That local playback difference was not evidence of degraded driver samples.
