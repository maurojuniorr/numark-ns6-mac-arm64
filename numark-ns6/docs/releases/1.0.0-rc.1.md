# Numark NS6 1.0.0-rc.1

This release candidate packages the validated modular 0.2.45 implementation with package version **1.0.0**. The GitHub prerelease tag is `v1.0.0-rc.1`. It includes separate CoreAudio devices named **Numark NS6 Output** and **Numark NS6 Input**, the MIDI bridge, Status app, automatic activation/recovery, and package cleanup of the legacy driver.

## What works

- Four-channel, 44.1 kHz Float32 playback and a separate two-channel stereo master/record input. Input and output use independent readers, rings, and CoreAudio devices.
- Bidirectional MIDI through the NS6's separate USB endpoints. The CoreMIDI bridge keeps the existing **Numark NS6** identity used by Mixxx mappings and forwards controller input and host output.
- The login bridge keeps CoreAudio attached to the output and reattaches after USB reconnection. Hardware testing confirmed that playback, capture, and MIDI resumed after reconnect without restarting the applications.
- The Status app reports controller firmware and active CoreAudio clients. The installer installs or updates it together with the driver and bridge; upgrade scripts remove the conflicting legacy driver/helper.
- A full uninstaller removes the driver, bridge, Status app, legacy helpers, and package receipts while preserving logs and user preferences.

## Problems resolved

- **TikTok LIVE Studio showed a zero input meter** even though OBS and macOS received the NS6 input. The driver advertised a zero-timestamp period of 512 frames, below CoreAudio's 10,923-frame minimum. The timestamp period is now 16,384 frames and is independent of the I/O buffer size. With 0.2.45, the TikTok meter moved from the NS6 input while Mixxx playback and MIDI remained normal.
- **Playback and MIDI could stop after USB reconnect or package update.** The bridge now owns a silent CoreAudio keepalive and watches for the device to return; hardware validation confirmed automatic recovery after reconnect.
- **Legacy installations could retain the USB interface.** Package upgrade hooks stop the old helper and remove the old driver before restarting CoreAudio.
- **MIDI responsiveness degraded while audio was playing.** The modular branch's MIDI scheduling/forwarding changes were verified with Mixxx during simultaneous playback; controls remained responsive in the successful 0.2.45 input test.

## Validation and known limits

The automated suite passed 14/14 tests on the source baseline. Hardware validation confirmed direct NS6 input capture in TikTok LIVE Studio, simultaneous Mixxx playback and MIDI operation, and automatic recovery after USB reconnect. Extended live-stream duration and other macOS versions remain to be tested.

The TikTok recording sounded muffled when played in QuickTime, but the decoded WAV and an AAC-LC conversion sounded clear. This points to a playback/decoder difference in that local QuickTime test; it was not evidence of degraded samples from the driver.
